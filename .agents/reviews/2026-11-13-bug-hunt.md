## 1. A digested key with an attribute is a different key from its plain text, and they overwrite each other — #105, high, reproduced
- Where: [R/key.R:133-140](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/key.R#L133-L140), [R/key.R:164](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/key.R#L164), [R/store.R:301-305](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/store.R#L301-L305)
- Trigger:

```r
long <- strrep("k", 600); g <- structure(long, note = "x")   # or class = c("glue", "character")
cache_set(s, g, "G")
cache_get(s, long, default = "MISS")   # "MISS"
cache_add(s, long, "second")           # TRUE, overwrites the entry
cache_get(s, g, default = "MISS")      # now "MISS" too
```

- Observed: Both spellings hash to the same stored key `#<sha256>`, but `store_record_matches()` compares the record's key text with `identical()`, and the attributed text keeps its attributes. So each spelling sees the other's record as a different key: gets miss, `cache_add()` succeeds and overwrites, and `cache_incr()` restarts at 1. Keys of 512 bytes or fewer are not affected, because they skip the text comparison. The attributes also leak into `cache_key()`, `cache_key_chr()`, `cache_key_text()$text` and `cnd$key`.
- Cause: `key_canon()` and `utf8_text()` return the string with its attributes.
- Fix: Strip attributes in `key_canon()` (`as.vector()`/`unclass()` on the text), and compare record key text as bytes.
- Family: 4. Siblings checked: `cache_key()`, `cache_key_chr()`, `cache_key_text()` and `cnd$key` carry the attributes too; keys of 512 bytes or fewer are unaffected.
- Test the suite lacked: for a key above `KEY_MAX` with a class or attribute and the same key without it: one entry, read back through both spellings; `cache_key()` of both is identical.
- Found by: R layer. Probes: `hunt-1/p09_attr.R`, `rerun/h1.R`

## 2. Namespace prefixes are not delimited: cache_forget_all() deletes other keys, and two cachem adapters reset each other's entries — #108, high, reproduced
- Where: [R/memoise.R:189-191](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/memoise.R#L189-L191)
- Trigger:

```r
ma <- cache_memoise(f, s, name = "q")
cache_set(s, "q/video", 1)
cache_forget_all(ma)
cache_has(s, "q/video")   # FALSE
```
Also `as_cachem(s, prefix = "cachem")` and `as_cachem(s, prefix = "cachem2")`: the first lists and `reset()`s the second's entries.

- Observed: `cache_forget_all()` evicts by the prefix `q/v`, so it removes any key starting `q/v`, including `q/video` and every version's entries. An adapter whose prefix lacks a separator owns every key that extends it, and its `keys()` returns `""` for a key equal to the prefix.
- Cause: The namespace prefix is matched as a raw string prefix, with no terminator.
- Fix: Forget each version as `<name>/v<digits>/`: scan `<name>/v` and keep a key only when digits then `/` follow. Have `as_cachem()` append a separator to its prefix, or refuse a prefix without one.
- Family: 4. Siblings checked: every place a prefix stands for a namespace: `cache_forget_all` and `as_cachem` (both found).
- Test the suite lacked: user keys `q/video`, `q/v`, `q/v1x` beside a memoised `q` with versions 1 and 10: forget_all removes only the memoised entries; two adapters `a` and `a2` are disjoint.
- Found by: R layer. Probes: `hunt-1/p06_memo.R`, `hunt-1/p07_cachem.R`, `rerun/h1.R`

## 3. Orphan or stale expiry and stored index rows hang cache_expire() and cache_cull(), and can delete live entries — #115, high, reproduced
- Where: [R/maintain.R:42-57](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/maintain.R#L42-L57), [R/maintain.R:118](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/maintain.R#L118), [R/maintain.R:231](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/maintain.R#L231)
- Trigger:

With `cull_limit = 2`, three `expiry` rows whose `meta` entry is gone, which `cache_check()` reports as `index_orphan`: `cache_expire(s)` never returns. The same with `stored` rows: `cache_cull(s)` never returns, and each `cache_set()` cull step counts phantom evictions (4) while the store stays over `size_limit`. A stale `expiry` row with an old deadline for an entry whose record expires in an hour: `cache_expire()` deletes the live entry and counts it expired.

- Observed: A hang, and the deletion of a live entry.
- Cause: The return value of `store_delete_entry()` is ignored, an orphan row is not removed, and the record's own `expire` is not re-checked before deleting.
- Fix: In the expire and evict walks, delete the index row when its entry is gone, and re-check the record's `expire` and `stored` before deleting the entry.
- Family: 3 (the tag walk handles orphan rows; the expire and evict walks do not). Siblings checked: the expire walk, the evict walk (`cache_cull` and the cull step on writes) and the tag walk, which holds.
- Test the suite lacked: insert `cull_limit + 1` orphan rows at the head of each index: `cache_expire()`/`cache_cull()` return, remove them, and delete no live entry.
- Found by: storage. Probes: `hunt-2/p5b.R`

## 4. A codec is identified by name alone: a same-name codec decodes with the wrong object, and a cache's compress setting is lost on reopen — #120, high, reproduced
- Where: [R/codec.R:361-373](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/codec.R#L361-L373), [R/record.R:40-55](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/record.R#L40-L55)
- Trigger:

```r
c1 <- codec("lines", encode = function(v, p) writeLines(v, p),      decode = function(p, m) readLines(p))
c2 <- codec("lines", encode = function(v, p) writeLines(rev(v), p), decode = function(p, m) rev(readLines(p)))
cache_set(s, "k1", c("1", "2"), codec = c1)
cache_set(s, "k2", c("1", "2"), codec = c2)
cache_get(s, "k2")   # c("2", "1")
```
And `cache(dir, codec = codec_rds(compress = TRUE))`: the config persists only the name `rds`, so a reopen without the argument writes uncompressed (108 bytes against 40031) with no notice.

- Observed: A wrong value, silently. The value is encoded with the call's codec and decoded with the codec first registered under that name.
- Cause: `codec_register()` keeps the first object for a name, and the record holds only the name and version.
- Fix: Refuse a second, different codec object under a registered name (`dazcache_codec_error`), and record codec parameters that change the bytes (rds `compress`) in the config and meta.
- Family: 1 (one name, two codecs). Siblings checked: built-in codecs with parameters (`codec_rds(compress =)`); `as_cachem(codec =)`.
- Test the suite lacked: two different codecs under one name, per call and per cache: refused, or each entry reads back its own value; a cache reopened without `codec =` keeps writing as configured.
- Found by: storage. Probes: `hunt-2/p9.R`, `rerun/h2.R`

## 5. Key encoding trusts a value's class: version objects recurse until the C stack overflows, and malformed factors, difftimes and data frames fail with bare errors — #106, medium, reproduced
- Where: [R/key.R:235](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/key.R#L235)
- Trigger:

```r
cache_key(packageVersion("rlang"))          # CStackOverflowError
cache_set(s, numeric_version("1.2"), 1)     # the same; also a memoised f(v = getRversion())
cache_key_chr(structure(5L, class = "factor", levels = c("a", "b")))  # simpleError "malformed factor"
cache_key_chr(structure(1, class = "difftime"))                           # simpleError
cache_key_chr(structure(list(), class = "data.frame"))                   # simpleError
```

- Observed: `numeric_version`, `package_version` and `vctrs::new_rcrd()` records recurse without end, and a list nested 3000 deep does the same. Malformed classed atomics escape as bare `simpleError`s. `cache_key_chr(structure("2026-01-01", class = "Date"))` returns `NA` with a warning.
- Cause: `canon_value()` and `canon_named()` call `vapply`/`lapply`, `[[` and `length` on the classed object. `as.list.numeric_version()` returns elements that are themselves `numeric_version`.
- Fix: Work on `unclass(x)` once the class has been decided. Validate the shape of each supported class (factor codes within the levels, `difftime` units present, a data frame's row count) and refuse others with `dazcache_key_invalid`. Cap the nesting depth.
- Family: 4. Siblings checked: every classed input `canon_value()` dispatches on: factor, Date, POSIXct/lt, difftime, data.frame, integer64, and lists with a class.
- Test the suite lacked: a table of malformed and exotic classed values (version objects, rcrd, malformed factor and difftime, a 0-column data frame, nesting 1e4 deep): each gives a text or `dazcache_key_invalid`, never another class.
- Found by: R layer. Probes: `hunt-1/p08_extreme.R`, `hunt-1/p15_confirm.R`, `rerun/h1.R`

## 8. Argument validation leaks conditions outside the dazcache_* taxonomy and treats siblings differently — #112, medium, reproduced
- Where: [R/cache.R:120-175](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/cache.R#L120-L175), [R/memoise.R:138](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/memoise.R#L138)
- Trigger:

```r
cache(dir, eviction = "lru")        # rlang_error (arg_match)
cache(dir, durability = 1)          # rlang_error
cache_incr(s, "c", 5)               # rlib_error_dots_nonempty
cache(dir, map_size = 4096)         # dazcache_engine_error "The storage engine failed"
cache(dir, map_size = 1e6 + 0.5)    # the same
cache_memoise(f, s, version = 2^31) # warning, key "f/vNA/...": every large version shares entries
cache_set(s, "k", 1, expire = as.POSIXlt(Sys.time()))   # refused as "NA or NaN"
```

- Observed: `map_size` is checked as a number only and then fails inside the engine. `version` above `.Machine$integer.max` becomes `NA` (a date-stamp version such as `20261113120000` qualifies), so bumping it does not invalidate. `inline_max = Inf` and `timeout = Inf` are refused while `size_limit = Inf` is accepted.
- Cause: `rlang::arg_match()` and `check_dots_empty()` raise their own classes; `map_size` has no range or page check; `as.integer()` follows a check that allows values past the integer range.
- Fix: Wrap `arg_match`/`check_dots_empty` so they raise `dazcache_type_error` (design.md line 191 chose `check_dots_empty()`; keep it but reclass). Validate `map_size` against the engine's minimum and alignment. Give `version` a maximum (or keep it a double). Accept `POSIXlt` in `expire`. Decide `Inf` for `inline_max` and `timeout` alike.
- Family: 3. Siblings checked: the `cull_limit` coercion is #94, the same shape. Check every `as.integer()` of a user number.
- Test the suite lacked: for every exported argument: NA, negative, fraction, `.Machine$integer.max + 1`, Inf and the wrong type, each raising a `dazcache_*` class (one table-driven test).
- Found by: R layer. Probes: `hunt-1/p03_args.R`, `hunt-1/p04_cache.R`, `hunt-1/p06_memo.R`, `rerun/h1.R`

## 10. Writing the same bytes never heals a damaged blob, and the new key is unreadable too — #114, medium, reproduced
- Where: [R/blob.R:59-63](https://github.com/pedrobtz/dazcache/blob/f3133d9/R/blob.R#L59-L63)
- Trigger:

```r
s <- cache(dir, inline_max = 100); x <- runif(100)
cache_set(s, "a", x); p <- cache_path(s, "a"); Sys.chmod(p, "0644"); writeBin(as.raw(1), p)
cache_set(s, "new", x)    # succeeds
cache_get(s, "new")       # dazcache_blob_corrupt
```

- Observed: The correct bytes are staged and then discarded. The recovery idiom in design.md §13 (catch `dazcache_blob_corrupt`, recompute, store) cannot work for that content until `cache_check(repair = TRUE)` runs.
- Cause: When a `blobs` row exists, `store_ref_blob()` only increments `refs`; it never checks that the file exists and has the recorded size.
- Fix: In the write transaction, check the existing file's size (a `stat`, cheap); if it is missing or wrong, publish the staged file over it.
- Family: 1 (a `blobs` row read as "the file is right" where it means "it was published once"). Siblings checked: the rename-over-orphan path already handles a file with no row.
- Test the suite lacked: truncate or delete a referenced blob, write the same value under a new key, and both keys read back.
- Found by: storage. Probes: `hunt-2/p4.R`, `rerun/h2.R`

```r

  cache_transact(s, { cache_set(s, "a", 1); signalCondition(simpleError("soft")); return("ret") })
  "late"
```

## Cross-cutting

- **Normalisation is applied per argument, not per kind of value.** Keys go through `key_canon()` and `start` through `key_start()`. `prefix` (#107) and attributed key text (#105) skip the step. Every value that is compared with stored key bytes should pass one function.
- **A name is trusted as identity.** A codec name stands for an object and its parameters (#120); a `blobs` row stands for a correct file (#114); a prefix stands for a namespace (#108). Each time, the name was right and the thing behind it was not.
- **Maintenance walks assume the indexes are true projections.** The tag walk tolerates orphan rows, the expire and evict walks do not (#115), and repair checks "counted" before "correct" (#116). That is family 3 inside one file.
- **Lifecycle state is updated in the wrong order.** `engine_close()` changes `refs`, closes the environment, then edits the registry, so any error in the middle leaves the three out of step (#122, #123, and #97). Update the bookkeeping first, then do the effect.
- **Candidate rule for `correctness.md`: a signalled condition is not an exit.** #124 sets a failure flag from a calling handler, so an `error` condition that is signalled but handled decides the transaction's outcome. Proposed wording: "Decide what an exit means from how the frame exits (an exiting handler, or `on.exit()` with a normal-return flag), never from conditions observed on the way." This fits none of the four families well; it is "a condition is an event, not a state". It belongs in `pedrobtz/packages`.

## Held: what was probed and stood

- **Key text:** about 125 values, every type, NA of each type, zero-length, names, latin1 and UTF-8. Byte-identical under `LC_ALL=C`, ISO8859-1, `OutDec = ","`, `scipen = -5`, `digits = 3`, `TZ` Asia/Kolkata and America/St_Johns. No collisions apart from #101; `1L`, `1`, `-0` and `integer64(1)` agree.
- **Model-based run:** 1500 random steps (set, mset, add, delete, pop, touch, incr, evict, expire, cull) compared with an R model after every step. Zero mismatches in values, keys, tags, counters and `cache_check()`.
- **Accounting:** blob bytes, modes, refcounts, `bytes_inline`/`bytes_blob` and `cache_volume()` match a recount from disk after every sequence tried (overwrite blob to inline to blob, pop, transact delete and re-set, expire, evict, clear).
- **Limits straddled:** `inline_max` at 99/100/101 (raw, rds, rds compressed); `size_limit` exactly at the limit and +1; `cull_limit` bounding; `CODEC_META_MAX` at 4095/4096/4097; tags at 16/17 and 256/257 bytes multibyte; counters across ±2^32.
- **Repair:** deleted `blobs` rows, wrong refs, counter drift, cleared index databases, deleted meta records, wrong `blobs.bytes`. Each repaired in one pass with surviving values correct, except #116.
- **Concurrency:** 8 processes × 40 rounds of incr plus same-bytes blob set, get, delete and pop gave n = 320, with no wrong bytes or orphans. 8 processes memoising one call: one entry. 8 processes creating one directory with conflicting config: one wins, the rest get `dazcache_config_conflict`.
- **Crash points** `publish`, `replace` and `unlink`: values and counters right, only orphan or `tmp_stale` findings. `SIGINT` in the busy loop, in a block and in a 300-blob `mset`: nothing committed, `tmp/` empty.
- **Transactions:** `return`, `break` and `next` commit (absent #124); error and interrupt abort; joined handles and `with_cache()` abort together; another directory's handle commits independently.
- **Fork:** an inherited handle in the child gives `dazcache_forked` for get, set and close, and the parent is unaffected. Busy: `timeout` 0, 0.5 and 5 s behave as documented.
- **Memoise and cachem:** argument equivalence, dots, omit, key functions, producers that write the same cache or nest, inside committed and aborted blocks, a `callr` producer; `memoise::memoise` and `cachem::cache_layered` interop.

## Not reached

- `#100` (counter row length) and the 5 s reap timeout under a held lock: the race was not won.
- Long-lived read snapshots: the API exposes none.
- `unloadNamespace()` during an open transaction, and `SIGINT` exactly during commit or reap.
- `as.list()` above 100,000 entries.
- `map_size` exhaustion mid-write and its effect on staged and published blobs.
- A blob replaced by a directory or symlink; an unwritable `blobs/<aa>`.
- The platforms listed as unverified above.

## Not reproduced, and by design

- **Nothing failed to reproduce.**
- **The rds header differs by locale**, so the same value has a different blob hash in different sessions. design.md expects this: identity comes from the key, never from `serialize()` output.
- **A nested block's caught error commits with the outer block.** This follows D21 (nested blocks join the outer). The `cache_transact()` help says a block that raises commits nothing, which is true of the outer block. Worth a sentence in the docs, not a fix.
- **`cache_set(s, c("p", "q"), v)` stores one key while `cache_has(s, c("p", "q"))` asks about two.** The read verbs take a vector of keys by design (code comment, design.md §3.2). It is a trap, but a recorded one.
- **`check_dots_empty()` raises rlang's class.** design.md chose `check_dots_empty()`; the reclassing is part of #112.
- **`cache_touch()` cannot revive an expired entry**, and an expired but unreclaimed entry still counts. Both follow lazy expiry (design.md §9.3).
- **A memoised call inside `cache_transact()` holds the lock across the producer.** This was decided in #104.
